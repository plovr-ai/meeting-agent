# Auto Meeting Title Design

## Context

GitHub issue #61 reports that meetings without an explicit agenda title currently keep process/window-style names such as "Google Chrome". After the meeting summary is generated, the app should replace generic titles with a concise title derived from the transcript.

## User Intent And Success Criteria

Managers should see a useful meeting title in the agenda and meeting list after summary generation, even when they did not prepare an agenda. A successful implementation updates only generic, system-derived names and preserves titles that a user entered through the agenda editor.

## Requirements

- Generate a concise meeting title as part of summary generation.
- Persist the generated title on `MeetingRecord.name` so agenda rows and selected meeting headers use it automatically.
- Preserve explicit agenda titles and other user-authored meeting names.
- Support local extractive summaries and OpenRouter summaries.
- Keep failed summaries from renaming the meeting.
- Keep old summary JSON compatible when the title field is absent.

## Non-Requirements

- No separate title-generation provider or background job.
- No new UI controls for accepting or rejecting generated titles.
- No title updates while recording is still in progress.
- No overwrite of names that look user-authored.

## Approaches Considered

### Selected: Summary-Carried Title

Add `autoGeneratedTitle` to `MeetingSummary`. Providers fill it when possible, and `MeetingAgentViewModel.generateSummary(for:)` persists it to `MeetingRecord.name` after a successful summary if the existing name is generic.

This approach reuses the existing summary workflow, artifact writing, and view-model persistence.

### Alternative: Separate Title Provider

A standalone title provider could generate names independently from summaries. This would be more flexible, but it adds another async workflow and more UI state for little current value.

### Alternative: UI-Only Derived Title

Agenda rows could show a derived title from `summary.json` without changing metadata. This avoids metadata mutation, but it would leave exports and other consumers with the stale process title.

## Architecture

`MeetingSummary` gains an optional `autoGeneratedTitle`. The field defaults to nil when decoding older artifacts.

`ExtractiveMeetingSummaryProvider` derives a title locally from meaningful transcript content. It prefers key topics, then overview text, normalizes whitespace, removes sentence-ending punctuation, and caps the result to a short single line.

`OpenRouterMeetingSummaryProvider` asks the model to return `autoGeneratedTitle` in its JSON. If the field is missing or blank, it uses the same local fallback used by extractive summaries.

`MeetingAgentViewModel.generateSummary(for:)` writes summary artifacts first, then updates and saves the matching `MeetingRecord` only when:

- `summary.status == .succeeded`
- `summary.autoGeneratedTitle` is non-empty
- the current name is generic or system-derived

Generic names include common browser/meeting app names, the default agenda placeholder, empty strings, and names that begin with app-window detection text. This keeps user-edited names intact.

## Data Flow

1. User stops recording and generates a summary, or regenerates a summary later.
2. The selected summary provider returns `MeetingSummary(autoGeneratedTitle: ...)`.
3. The view model writes `summary.json` and `summary.md`.
4. The view model conditionally renames the meeting record and saves `metadata.json`.
5. Existing agenda and workspace UI refresh from `meetings`.

## Error Handling

If summary generation fails, the meeting title is unchanged. If the generated title is blank after normalization, the title is unchanged. If metadata saving fails, `generateSummary(for:)` throws after summary artifact writing, matching the existing persistence behavior for required outputs.

## Testing

- `MeetingSummaryTests` covers backward-compatible decoding when `autoGeneratedTitle` is absent.
- `MeetingSummaryProviderTests` covers local title generation and OpenRouter title parsing/fallback.
- `MeetingAgentViewModelTests` covers generic-title replacement and user-authored-title preservation.
- Full verification uses `make test`.
