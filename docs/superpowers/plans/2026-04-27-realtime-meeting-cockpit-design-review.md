## Scope

This review covers the phase 1 macOS app cockpit UI for live bilingual captions, meeting goal status, health states, and suggested follow-up questions.

Classifier: **APP UI**.

This is a dense, task-focused meeting workspace. It should not look like a landing page, a generic SaaS dashboard, or a card mosaic.

## Initial Rating

Overall design completeness: **5/10**.

The CEO and engineering plans define the product architecture well, but the UI plan still lacked concrete screen hierarchy, caption-turn structure, interaction states, accessibility behavior, and the exact relationship between captions and goal tracking during a live meeting.

A 10/10 plan for this feature defines:

- what the user sees first, second, and third during a live meeting
- how original and translated captions are paired
- how translation lag is shown without harming comprehension
- how goal status and unresolved issues are summarized
- how suggested questions become immediate action
- all loading, empty, error, partial, and success states
- compact macOS window behavior
- keyboard, selection, copy, contrast, and screen-reader requirements

## Information Architecture

Rating: **5/10 -> 9/10** after this review.

The cockpit must use a strict 70/30 hierarchy:

```text
LiveMeetingDashboardView
|
+-- Top status bar
|   +-- LIVE / READY indicator
|   +-- elapsed time
|   +-- meeting name
|   +-- source -> target language
|   +-- health chips: captions / translation / analysis
|
+-- Main content, horizontal split
|   |
|   +-- Left pane, 70% width: Live captions
|   |   +-- current/final caption stream
|   |   +-- each turn pairs original text above translated text
|   |   +-- speaker/time metadata kept small
|   |   +-- translation pending/failure shown inline per turn
|   |
|   +-- Right pane, 30% width: Goal cockpit
|       +-- meeting goal title and current status
|       +-- objective checklist
|       +-- unresolved items
|       +-- suggested questions, Chinese + English
|       +-- one-click copy English question
|
+-- Bottom compact action row
    +-- goal edit/review entry, disabled while recording if needed
    +-- stop recording
    +-- export/copy actions after meeting
```

First 5 seconds:

1. User sees live caption stream.
2. User sees whether translation/analysis is healthy.
3. User sees whether the meeting goal is on track.

Constraint rule: if the window can only show three things, show **captions, health, and one best suggested question**.

## Caption Turn Design

Each caption turn should be a row, not a decorative card:

```text
[Speaker 1] [00:12] [final]
Original text in source language, larger and highest contrast.
Translation in target language, slightly smaller, muted until final.
```

Rules:

- Original text is always primary because it is the trusted source.
- Translation sits directly below the original text to preserve pairing.
- Pending translation uses a short muted status: `Translating...`.
- Failed translation keeps original text and shows a compact retry/status marker.
- Final captions use full text contrast; partial captions use muted text.
- New turns should not resize old turns unexpectedly.
- Long turns wrap inside the pane and preserve readable line height.

Do not split original and translation into two separate columns in phase 1. Users need eye tracking to be simple during a live call.

## Goal Cockpit Design

The right pane is a meeting coach, not a report.

Hierarchy:

1. Meeting goal and status.
2. Objective checklist.
3. Unresolved items.
4. Suggested questions.

Status language should be short:

- `On track`
- `Partially covered`
- `Blocked`
- `Not started`
- `Analysis delayed`

Suggested question row:

```text
Ask next
中文：我们是否已经确认上线负责人和截止时间？
EN: Have we confirmed the launch owner and deadline?
[copy English]
```

Rules:

- Show 1-3 suggested questions only.
- Rank by meeting usefulness, not model confidence text.
- English copy button should use an icon+label or compact button aligned right.
- Copied state should be visible for 1-2 seconds: `Copied`.
- Do not show long model reasoning in the live UI.

## Interaction State Coverage

Rating: **4/10 -> 9/10** after this review.

| Feature | Loading | Empty | Error | Success | Partial |
|---|---|---|---|---|---|
| Captions | `Listening...` with caption health chip | `Waiting for speech` plus recording status | `Caption unavailable`, WAV recording still live | final turns stream in order | partial turn muted until final |
| Translation | per-turn `Translating...` | hidden until first final segment | `Translation delayed` on turn and health chip | translation appears below original | original stays visible while translation lags |
| Goal status | `Analyzing goal...` | `Add meeting goal` before recording, `No goal set` during recording | `Analysis delayed`, previous state remains | status + objectives update | stale state marked with updated time |
| Suggested questions | hidden until enough context | `No question yet` | keep last good suggestion, health chip degraded | 1-3 bilingual suggestions | suggestions marked as based on partial progress |
| Progress persistence | not user-facing | not user-facing | status chip `Progress not saved` | no UI noise | retry silently, expose health if repeated |
| Post-meeting summary | `Generating summary...` | `No transcript yet` | clear failure with retry/export transcript available | summary includes goal outcomes | summary notes missing progress or transcript |

Empty states must be useful:

- Before a meeting goal exists, show a compact goal setup prompt.
- Before speech arrives, show listening status and health chips.
- Before suggestions exist, reserve only one quiet line, not an empty panel.

## User Journey

Rating: **5/10 -> 9/10** after this review.

```text
STEP | USER DOES | USER FEELS | DESIGN SUPPORT
-----|-----------|------------|---------------
1 | Opens app before meeting | wants control before call starts | goal template is visible, compact, not modal-heavy
2 | Starts or joins meeting | cannot miss live status | top bar shows LIVE, time, language, health
3 | Listens across languages | needs trust and low effort | original text first, translation paired below
4 | Translation lags | worries about missing meaning | original remains readable, translation health is honest
5 | Meeting drifts | needs a timely prompt | right pane shows status and one best question
6 | Copies English question | wants immediate action | one-click copy with clear copied feedback
7 | Meeting ends | wants alignment artifact | summary uses transcript plus progress state
```

5-second visceral goal: "I can understand this meeting right now."

5-minute behavioral goal: "I know whether we are getting to the decision."

5-year relationship goal: "This app is dependable in messy cross-border meetings."

## AI Slop Risk

Rating: **7/10 -> 9/10** after this review.

Avoid these patterns:

- generic dashboard card grid
- decorative gradient backgrounds
- large marketing hero
- centered explanatory text
- icon-in-circle feature blocks
- verbose AI explanation panels
- stacked cards inside cards

Required visual posture:

- calm dark app surface
- dense but readable caption stream
- restrained chips and separators
- one accent color for primary actions
- no decorative images
- no explanatory onboarding copy inside the live meeting surface

The existing command-center style is acceptable, but the current brown/dark palette can drift too far into a one-note dark theme. The cockpit should use teal only for primary status/action, warning for delayed states, red for failure, and muted text for metadata. Do not add more accent colors for each objective.

## Responsive And Accessibility

Rating: **4/10 -> 8/10** after this review.

Desktop macOS window targets:

- Preferred width: 1180-1440px.
- Minimum useful width: 980px.
- Left pane minimum: 620px.
- Right pane minimum: 320px.
- If width is too narrow, right pane should collapse below captions or become a tab/segmented view. Do not squeeze captions below readability.

Accessibility requirements:

- Body/caption text should be at least 16px.
- Original caption contrast must meet 4.5:1 against the background.
- Translation text may be visually secondary but still must remain readable.
- Buttons and copy controls should have at least 34px macOS hit height; 44px where touch-like affordance is used.
- All text in captions and suggestions should support selection.
- Suggested question copy action must be keyboard reachable.
- Health chips need text labels, not color-only meaning.
- VoiceOver labels should distinguish original caption, translated caption, meeting goal status, and suggested question copy action.
- Long speaker names, project names, and acronyms must truncate or wrap without overlapping controls.

## Unresolved Design Decisions

Resolved in this review:

1. Original and translation are vertically paired in one caption turn.
2. Captions remain the dominant left pane; goal state stays in a right pane.
3. Suggested questions show Chinese and English, with one-click English copy.
4. Health states are always visible in the top bar and specific failures appear near the affected content.
5. The UI uses the existing command-center design language.

Deferred:

1. Full `DESIGN.md` creation.
2. Visual mockup approval through gstack designer.
3. Always-on-top/floating window behavior.
4. Mobile layout. This is a macOS app; only narrow desktop behavior is in scope.
