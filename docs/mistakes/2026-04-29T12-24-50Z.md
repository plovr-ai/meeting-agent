# [102] Keep SwiftPM verification serial per worktree

**Date**: 2026-04-29
**Category**: test-mistake

### What went wrong
While verifying focused summary tests, two `swift test --filter ...` commands were launched in parallel in the same worktree, repeating a known mistake and causing the later coverage run to produce an empty report from shared SwiftPM scratch state.

### Correct approach
Run SwiftPM build, test, and coverage commands one at a time in a worktree unless each command uses an isolated scratch path.

### How to avoid
Before running SwiftPM verification, check whether another SwiftPM command is active in the same worktree and serialize the commands.
