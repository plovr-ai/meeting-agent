# [156] Treat partial persistence outcomes consistently

**Date**: 2026-05-15
**Category**: logic-error

### What went wrong
The first refinement service implementation saved the refined caption document and then threw if saving refinement metadata failed, which could report refinement failure after `transcript.json` had already been replaced.

### Correct approach
Once the refined transcript document is durably written, report refinement success and treat metadata persistence as best-effort, so the returned status matches the transcript source of truth.

### How to avoid
When a workflow writes multiple persistence artifacts without transactions, decide which write establishes the source-of-truth outcome and do not report the opposite state after that point.
