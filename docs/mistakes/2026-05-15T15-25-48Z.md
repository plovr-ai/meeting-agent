# [155] Microphone attribution must cover both STT output paths

**Date**: 2026-05-15
**Category**: wrong-assumption

### What went wrong
The first implementation instinct was to treat microphone attribution as a speech-event-only concern. That would cover Deepgram-style realtime events but could miss providers that publish through `TranscriptUpdateSink`, including local or Whisper-backed paths.

### Correct approach
Attribute the microphone stream at the provider boundary for both `SpeechRecognitionEventSink` and `TranscriptUpdateSink`, then forward standard events and transcript updates downstream with the local-user speaker label.

### How to avoid
When changing realtime transcription behavior, check every provider output surface before choosing the adapter boundary.
