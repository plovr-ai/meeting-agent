# [151] Split active shared types before deleting legacy modules

**Date**: 2026-05-15
**Category**: wrong-assumption

### What went wrong
While removing historical translation assets, I initially treated `BilingualProvider.swift` as purely legacy translation code. It also contained still-active provider catalog and audio transcription protocol types, so deleting the whole file broke the Swift build.

### Correct approach
Before deleting a mixed-responsibility legacy file, search for live type references and move any still-active shared boundary types into a neutral file with focused tests.

### How to avoid
For removal issues, classify each deleted file by exported symbols and current references, not by filename alone. If a file mixes legacy and active abstractions, split first and delete only the obsolete surface.
